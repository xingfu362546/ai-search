# 6Q 超级搜索 v6 · 全站智能检索版本规划

> 版本定位：v5 是「报读优先 + 降级跳转」的最小闭环。v6 改为**全站唯一检索入口**——8 类数据全部在 AI 智搜内呈现，按意图命中，不再有「暂不支持 / 去全部看看」。

---

## 1. 与 v5 的根本差异

| 维度 | v5（现行） | v6（本版） |
|------|-----------|-----------|
| 检索范围 | 只做课程/报读/期数/导师 | **8 类全站数据** |
| 意图枚举 | `course_enroll` / `other` | 扩到 8 类 + 兜底 |
| 未命中处理 | 「小Q暂不支持其他类型的智能检索哦」+「去全部看看」跳转 | **不再提示、不再跳转**，在对话内呈现 |
| 结果编排 | 只有期数卡 | 固定 8 分区瀑布，命中才出现 |
| 承载位置 | AI 智搜 + 全部 Tab 双轨 | **统一收敛到 AI 智搜** |

**要删掉的现行逻辑**（原型与方案里都有）：

- `AI_UNSUPPORTED_IN_CHAT` 正则与「小Q暂不支持」话术
- `go_all` / `open_all_search` 跳转胶囊（携带 keyword 切 Tab）
- `intent-slots-v5.json` 的 `intent_codes.other` 降级分支
- `ai-search-dify-architecture-draft.html` 第 6 节「意图不完整时的降级策略」

## 3. 结果编排（已定：B · 按意图命中）

### 3.1 规则

- 智能体先判意图，**只出命中类型的卡片**；未命中的类型不占位、不出现空壳。
- 一次问句命中多类时（如「恋爱咨询」可能同时命中文章+视频+音频），按固定顺序并列展示。
- 命中 0 类或意图不明 → 走**泛搜兜底**（8 类并行检索，按相关度混排），不再提示「不支持」。
- 多轮续聊时，每轮各自判定意图，结果追加在对话流中，不互斥。

### 3.2 固定展示顺序

```
线上课程 → 线下课程 → 领袖营 → 高EQ导师 → 6Q商城 → 文章 → 视频 → 音频
```

理由：课程类优先（业务主目标），实体类（导师）其次，内容类（文章/视频/音频）最后，商品垫在中间。

### 3.3 每类条数

- 单类命中：最多 5 条 + 「更多」展开（展开后同页追加，不跳页）。
- 多类命中：每类最多 3 条 + 「N 条」计数。
- 具体条数与交互在原型里演示两档，评审定稿。

## 4. 意图识别扩展

### 4.1 意图枚举

| intent | 触发语义 | 检索目标 |
|--------|---------|---------|
| `online_course` | 网课、录播、专栏、线上学 | 线上课程 |
| `offline_course` | 开班、开课、期数、报名、城市+课 | 线下课程 / 期数 |
| `leader_camp` | 营、夏令营、集训、亲子营 | 领袖营 |
| `mentor` | 导师、老师、谁讲、擅长 | 高EQ导师 |
| `mall_goods` | 买、盲盒、公仔、潮玩、价格 | 6Q商城 |
| `article` | 文章、干货、原理、怎么理解 | 文章 |
| `video` | 视频、讲解、看、短视频 | 视频 |
| `audio` | 音频、听、录音、电台 | 音频 |
| `general` | 无法归类或跨多类 | 8 类并行 + 混排 |

### 4.2 抽参字段（各类独立）

- 共用：`keyword`（原 query，必填，全链路透传）
- 课程类：`course_name` `city` `phase_no` `time_window_days` `instructor_name`
- 内容类：`topic` `author` `duration_range`
- 商品类：`goods_name` `goods_type`(实物/盲盒) `price_range`
- 导师类：`mentor_name` `specialty`

### 4.3 输出 Schema

```json
{
  "intents": ["article", "video"],
  "keyword": "恋爱咨询",
  "confidence": 0.86,
  "slots": {
    "common": { "keyword": "恋爱咨询" },
    "offline_course": { "course_name": null, "city": null },
    "mall_goods": { "goods_type": null }
  },
  "missing": []
}
```

注意 `intents` 改为**数组**——单次问句可命中多类，这是 v6 与 v5 最大区别。

## 5. 检索链路

```
用户输入
  → Dify 节点①：意图分类 + 抽参（intents[] + slots）
  → BFF 按 intents[] 并行调用各类检索接口（多类并发，单类超时不影响其他）
  → 聚合结果 → SSE 流式返回：导语文案 + 各分区 cards
  → APP 按固定顺序渲染分区（空类to不渲染）
```

无命中时：

```
intents 为空 / 全类 0 条
  → 泛搜兜底：8 类并行 + 相关度混排
  → 仍为 0 条：小Q 回复「没找到相关的内容，换个说法试试」
```

**注意**：兜底话术是「没找到内容」，不再是「暂不支持该类型」——这是语义上的关键区别。

## 6. 待确认项（阻塞原型与字段契约）

### 6.1 需要截图 / 说明的 3 类

| 类型 | 不确定点 | 影响 |
|------|---------|------|
| 线下课程 | 列表卡是「课」维度还是「期」维度（「高EQ智慧父母」1 条，还是「第533期·广州」1 条） | 决定检索接口粒度、去重逻辑 |
| 领袖营 | 与线下课程是并列还是子集；是营期活动还是课程 | 决定是否独立接口 |
| 高EQ导师 | 是导师个人主页卡（头像/职称/擅长/在授课程数）还是「高EQ」课程系列 | 决定是否要「推荐人」语义，与推荐期数完全不同 |

### 6.2 技术侧

- 8 类是否都有现成检索接口，缺哪些
- 小程序 / APP 端是否有统一的类目 Tab 壳可复用，或全部重构

## 7. 交付拆分

### v6.0 全站检索主链路（P0）

| 编号 | 功能 |
|------|------|
| 6.0.1 | 意图枚举扩到 8 类 + `general`，输出 `intents[]` |

## 8. 验收用例

| # | 输入 | 期望意图 | 期望呈现 |
|---|------|---------|---------|

## 10. Dify DSL 接入

用户后续提供 DSL 导出文件，用于：

1. 核对实际节点结构与本文 §5 链路是否一致（意图分类节点、HTTP 请求节点、分支节点）
2. 提取 Prompt 原文，避免我重写时偏离现有能力
3. 提取变量名（`keyword` / `intents` / slots），保证 BFF 口径一致
4. 检查是否已有 8 类检索的 HTTP 节点，缺哪几类

DSL 文件处理原则：**只读解析，不外传、不整段粘贴进公开仓库**；抽取结论写成本文与 `intent-slots-v6.json`。
