# Dify DSL · 全站检索版（内容类走系统接口）

`ai-search-v6.yml` 是在生产 DSL「（生产勿动）AI超级搜索（加课程说明）」基础上改出的工作流，可直接导入 Dify。

生成脚本：`scripts/build-dsl-v6.py`。改了 Prompt 或节点后重跑脚本，不要手工改 yml。

```powershell
python scripts/build-dsl-v6.py
python scripts/simulate-dsl.py dsl/ai-search-v6.yml      # 分支走向模拟
python scripts/preview-dsl.py dsl/ai-search-v6.yml output/preview.png   # 画布预览
python scripts/check-node38.py                          # 组装节点单测
```

画布效果见 `docs/diagrams/05-DSL-v6-画布布局.png`。

## 二、导入后必须做的 1 件事：回填 7 个接口

3.1 ~ 3.7 是 7 个 `HTTP 请求` 节点，标题带「待回填」，URL 统一写成：

```
https://FILL-ME.example.com/api/xxx/list
```

**不改就会报错**（域名不存在）。逐个节点打开，按下表填：

| 节点 | 类目 | 回填内容 |
|------|------|----------|
| 3.1 HTTP-线上课程 | `online_course` | 地址、方法、鉴权 |
| 3.2 HTTP-领袖营 | `leader_camp` | 同上；营期接口优先 |
| 3.3 HTTP-高EQ导师 | `mentor` | 同上 |
| 3.4 HTTP-6Q商城 | `mall_goods` | 同上 |
| 3.5 HTTP-文章 | `article` | 同上 |
| 3.6 HTTP-视频 | `video` | 同上 |
| 3.7 HTTP-音频 | `audio` | 同上 |

### 入参（已预设，可按接口调整）

```json
{
  "userId": "{{#1711528708197.user_id#}}",
  "sessionId": "{{#1711528708197.session_id#}}",
  "keyword": "{{#1781491262356.keyword#}}",
  "city": "{{#1781491262356.city#}}",
  "page": 1,
  "size": 20
}
```

- `keyword` 是清洗后的检索词，`city` 只在用户提到城市时有值
- 鉴权当前是「无」，需要 token / 签名时在该节点的 Authorization 里补
- 请求方式固定 `POST` + `Content-Type: application/json`，改 GET 时把 `page/size` 挪到 params

### 出参（唯一硬要求）

返回 JSON，列表项至少要有 **标题** 和 **id**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 去重与前端跳转用；字段名可不同，见下方别名表 |
| `title` | 是 | 卡片主文案 |
| `cover` | 否 | 封面图 |
| `url` | 否 | 详情页地址；空则由前端按 `type + id` 拼 |
| `summary` / `price` / `duration` / `author` / `specialty` | 否 | 各类目按需 |

列表包裹层级不限，3.8 会自动在 `data` / `result` / `list` / `records` / `rows` / `items` / `content` 里找第一层数组，支持嵌套一层（如 `{"data":{"records":[...]}}`）。

### 字段名不一致怎么办

改 **3.8 代码节点的 `ALIAS` 映射**，不要改节点结构、也不要加中间代码节点：

```python
ALIAS = {
    "id": ("id", "courseId", "goodsId", ...),
    "title": ("title", "name", "goodsName", ...),
    ...
}
```

把接口实际字段名加进对应元组即可，靠前的优先。
若某类目字段完全对不上，可在 `normalize()` 里为它单独加分支。

### 调试

3.8 输出 `debug_text`，形如 `文章 2/2、视频 0/1`（左为出卡数，右为接口原始条数）。
导入后先在 Dify 的「运行历史」里看这个字段：

- `0/0` = 接口没返回数据，或列表层没找到（先看 body 原文）
- `0/N` = 有数据但被丢弃，通常是缺 `title` 或 `id`
- 中文类目名对不上 = intents 没命中该类

## 三、节点结构

```
2.1 开始
 └ clean_history → 2.3A shown 清洗
    └ 2.2 意图识别（8 类，intents 数组，temperature 0.1）
       └ 2.3 解析意图
          └ 2.4 主路由
             ├ CASE1 有课程名 → 2.15A → 2.15B → 2.15C → 2.15 → 2.16 → 2.17 → 2.9 / 2.9B → 2.13
             ├ CASE2 只有城市/导师 → 2.15D → 2.16 → …
             ├ CASE3 内容类 → 2.4B
             ├ CASE4 闲聊 → 2.18 → 闲聊回复
             └ ELSE → 没找到内容

课程链出口（2.13 / 2.12 / 课程异常 / 补充信息）→ 2.4B

2.4B ─┬─ 3.1 线上课程 ─ 3.2 领袖营 ─ 3.3 导师 ─ 3.4 商城
      │      ─ 3.5 文章 ─ 3.6 视频 ─ 3.7 音频
      └→ 3.8 解析组装 → 3.9 是否有结果
                             ├ 有 → 3.10 导语 → 3.11 卡片回复
                             └ 无 → 3.12 内容未找到
```

- **2.4B** 是课程与内容并存的开关：课程答案先出，再接着出内容分区
- **3.9** 判断内容是否有结果，无结果直接走未找到，避免空导语
- 7 个接口节点**串行**，命中几个类目就由 3.8 只组装几个；未命中的接口返回空数组即可
- 画布按泳道摆：入口在左，课程链横向展开，出口收成一列，内容链接在右侧竖排

## 七、已知限制

1. **7 个接口串行**：命中 1 个类目也会依次调完 7 个。未命中的类目请让接口快速返回空数组；如果后端愿意提供统一聚合接口，可把 3.1~3.7 合并成 1 个节点，3.8 的入参相应改成单个 body。
2. **没有分页**：只取前 20 条、每类展示 3 条，做不了「共 128 条、查看全部」。
3. **接口失败会中断**：任一接口 4xx/5xx，整条内容分支报错，不会静默降级。回填前请先在 Dify 里单节点调试。
4. **导师类**：没有导师实体数据时该类永远为空，会静默不渲染。
5. **画布偏宽**：约 6100×1900，导入后按「适应画布」查看。
