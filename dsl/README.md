# Dify DSL · v6

`ai-search-v6.yml` 是在生产 DSL「（生产勿动）AI超级搜索（加课程说明）」基础上改出来的 v6 工作流，可直接导入 Dify。

生成脚本：`scripts/build-dsl-v6.py`。改了 Prompt 或节点后重跑脚本，不要手工改 yml。

```powershell
python scripts/build-dsl-v6.py "<生产 yml 路径>" "dsl/ai-search-v6.yml"
```

## 一、这一版改了什么

| 位置 | 改动 |
|------|------|
| 2.2 意图节点 | Prompt 换成 8 类数组版，temperature 0.8 → 0.1 |
| 2.3 解析节点 | 新增 intents / has_course / has_content / social_chat / topic，旧字段全保留 |
| 2.4 主路由 | 4 个 CASE：课程名明确 / 只有城市导师 / 内容类 / 闲聊；ELSE 没找到 |
| 2.4B | 新增。课程链跑完后判断是否还要补内容类 |
| 3.1–3.5 | 新增内容类链路：知识库检索 → 占位接口 → 组装分区卡 → 导语 → 回复 |
| 兜底节点 | 删掉「去全部看看」按钮，改为「没找到内容」 |
| 线下课程链 | **未改动**，2.15A→2.15B→2.15C→2.15/2.15D→2.16→2.17→2.13 原样保留 |

验证过：29 个节点、37 条边，无悬空引用、无不可达节点、if-else 出口全部存在。全局已无「去全部看看」「暂不支持」。

## 二、导入后必须填的 3 处

### 1. 知识库数据集（3.1 节点）

```yaml
dataset_ids:
  - 【待建数据集-6Q内容库】
```

把占位换成真实数据集 ID。数据集里每篇文档按下面格式写，否则 3.3 解析节点会丢弃：

```
title: 恋爱咨询是不是骗局？先看清这三件事
type: article
summary: 三个常见误区
cover: https://cdn.6qedu.cn/article/1024.jpg
url: https://www.6qedu.cn/article/1024
author: 6Q编辑部
```

- `type` 只允许：`article` / `video` / `audio` / `mentor`
- `url` 必填，缺了不出卡（点击无跳转等于不可用）
- 检索模式与现有课程库一致：混合检索，向量 0.6 / 关键词 0.4，qwen3-rerank，top_k 10

### 2. 接口占位节点（3.2）

线上课程、领袖营、6Q商城三类接口还没有。现在是一个返回空数组的 code 节点，**不伪造数据**。

开发接入时把 3.2 替换成 HTTP 节点，入参出参见节点内注释：

- 入参：`keyword`、`intents`、`city`
- 出参：`items`，每项含 `id`、`type`、`title`、`cover`、`url`
- 线上课程补 `price`；领袖营补 `camp_type`、`start_date`；商城补 `price`、`main_image`、`sales`

替换后把 3.3 的变量 `stub_json` 指向新节点的 `body`，并改成 JSON 解析即可。

### 3. 课程期数接口（2.15 / 2.15D）

沿用生产接口，未改。若后端调整入参，同步改这两个节点的 body。

## 三、节点地图

```
2.1 开始
 └ clean_history
    └ 2.3A shownSessionIds 清洗
       └ 2.2 意图识别 v6
          └ 2.3 解析 v6
             └ 2.4 主路由
                ├ CASE1 课程名明确 → 2.15A → 2.15B → 2.15C → 2.15 → 2.16 → 2.17 → 2.9 / 2.9B → 2.13
                ├ CASE2 只有城市导师 → 2.15D → 2.16 → ...
                ├ CASE3 内容类 → 3.1 → 3.2 → 3.3 → 3.4 → 3.5
                ├ CASE4 闲聊 → 2.18 → 闲聊回复
                └ ELSE → 没找到内容
课程链终点（2.13 / 2.11 / 2.12 / 课程异常 / 补充信息）→ 2.4B → 3.1
```

`2.4B` 是本次多类并存的关键：课程答案先输出，再接着输出内容类分区，两段都会进同一条消息。

## 四、已知限制

1. **串行执行**：8 类不是并行，命中课程+内容时是先后跑。首屏耗时会叠加，接口齐了再评估并行。
2. **知识库召回上限**：top_k 10，每类最多取 3 条，做不了「共 128 条、查看全部」。
3. **商城价格**：知识库只能出目录，价格必须等接口，别从知识库读 `price`。
4. **导师类依赖数据**：没有导师实体数据时，`mentor` 类永远空，会静默不渲染。

## 五、验证方式

导入后依次用这几句跑一遍：

| 输入 | 期望 |
|------|------|
| 智慧父母一阶 | 只出课程期数卡，与生产一致 |
| 恋爱咨询 | 出文章 / 视频 / 音频分区 |
| 你好 | 只回一句闲聊，不触发检索 |
| 夏令营 | 内容分区为空（接口未接）→ 走「没找到」 |
| 智慧父母一阶有没有相关文章 | 课程分区 + 文章分区，两段依次出现 |
